# Interview Portfolio

Student-facing material for the STEM Link DSA sessions: starter files and test specifications.

## Getting started

Do these once, in DSA Session 01:

1. Fork this repository on GitHub, so you have your own copy.
2. Run `git clone` with your fork's web address.
3. Open the `dsa-01-sales-log-and-undo` folder inside your clone in VS Code.

## At the start of each session, from DSA Session 02

1. Push your commits from the last session.
2. On your fork's GitHub page, choose Sync fork, then Update branch. Never choose Discard commits, which deletes your work.
3. Run `git pull`.
4. Open this session's folder in VS Code, and work inside it.

## Rules

- Each starter file holds the classes, methods and functions to build. Replace each `raise NotImplementedError` with your code. Never change a name, a parameter, a type hint or a docstring.
- Record each problem in `PORTFOLIO.md` at the root of your fork, in the format the -tests PDF gives.
- Your fork is public. It is your interview portfolio: every problem you solved, with your approach and its cost.
